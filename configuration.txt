1. change directory to the main folder by typing in terminal
  cd folder_path (cd means change directory)
  git init
  git status

2. adding specific file like config.js
  git add config.js

3. adding folder (adding all files in a folder, for example src folder)
  git add src

4. adding everything
  git add .

5. git status

6. git commit -m "message" (commit=version, m means we are attaching a message to the version or commit)

7. git log 
  to exit, press q
  to get all commit history
    git log --all
  to get branches of history
    git log --all --graph

8. to remove staged file config.js type manually:
  git reset config.js
  or all files in an src folder
  git reset src 

9. to remove all staged files/folders
  git reset .

10. to reset all changes (unstaged)
  git checkout -- config.js
  for all files:
  git checkout -- .

11. to go back to a particular commit uisng a commit hash 4ad3307c09611d7f27e8fe1e872f798830f59092
  git checkout 4ad3307c09611d7f27e8fe1e872f798830f59092

12. to go back to a branch name master
  git checkout master

13. to go back a version of a specific file config.js with commit hash 4ad3307c09611d7f27e8fe1e872f798830f59092
  git checkout 4ad3307c09611d7f27e8fe1e872f798830f59092 config.js

14. to go back a version of a specific folder src with commit hash 4ad3307c09611d7f27e8fe1e872f798830f59092
  git checkout 4ad3307c09611d7f27e8fe1e872f798830f59092 src

15. to go back to a previous version or commit without moving the HEAD
  git checkout 4ad3307c09611d7f27e8fe1e872f798830f59092 .

16. to set an alias or shortcut for git command git status using letter s
  git config --global alias.s "status"

17. to set an alias or shortcut for git command git commit -m using letter command
  git config --global alias.cm "commit -m" 

18. to remove git from the main folder
  rm -rf .git

git repository = a repository with changes monitored by git

there is only 1 HEAD, and it is current branch you opened in the editor.
the green text master pointed at the latest commit.
the green text bug_fix pointed also at the latest commit in its own branch.
the red text origin/master means that the GH remote repo origin branch has this latest commit into your local repo main branch master.
the red text origin/HEAD is the head of GH origin remote repo branch origin.
the red text origin/bug_fix is where the latest GH commit for the local branch bug_fix.


branching = working on multiple things at the same time
main branch = main/origin branch
scenario:
you create a branch bug_fix to work for a bug fix, then after fixing the bug in bug_fix branch, you merge the branch into the main branch and continue creating the feature in the original main branch

1. creating a branch bug_fix
  git branch bug_fix (naming branch is based on what you're working on)

2. switching branch bug_fix
  git checkout bug_fix

merging = combine the changes of all branches
 when you merge, the result will be saved in the current branch
 for example, current branch is master, and you want to merge the branch bug_fix to master branch, so the changes in bug_fix branch will be merged into the master branch
 the result is that a new commit will be placed on top of bug_fix branch

3. to merge bug_fix into the master branch (the current branch should be the master branch)
  git merge bug_fix -m "merged bug_fix into master branch"
